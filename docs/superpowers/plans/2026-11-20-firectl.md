# firectl Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `firectl`, a one-shot Rust CLI to query and edit Firestore (native mode) documents, safe for LLM agents.

**Architecture:** A pure, typed core (paths, values, queries, writes, write policy, typed-JSON codec) with no I/O; an `app` layer that turns a parsed command into calls on a `Firestore` port trait and returns an `Output` value; one gRPC adapter (`gcloud-sdk` raw protos) implementing the port; thin `cli`/`main` and `render` edges. Flow: `argv → cli::Cli → app::Request → (policy check) → Firestore port → Output → render → stdout + ExitCode`.

**Tech Stack:** Rust (edition 2024, toolchain from nixpkgs, rustc 1.99), tokio, clap 4 (derive) + clap_complete 4.6 (`unstable-dynamic`), gcloud-sdk 0.34 (`google-firestore-v1`, `google-firestore-admin-v1`), serde_json, chrono, base64, comfy-table, thiserror, itertools 0.15. Dev: assert_cmd, predicates, pretty_assertions. Nix flake with crane.

**Spec:** `docs/superpowers/specs/2026-11-20-firectl-design.md`

## Global Constraints

- Code lives at the repository root; the flake is `flake.nix`. All commands below run from the repository root inside `nix develop`.
- **Zero warnings:** `cargo clippy --all-targets -- -D warnings` and `cargo build` must be clean at the end of every task.
- **Lints** (in `Cargo.toml`): `unsafe_code = "forbid"`, `missing_debug_implementations = "warn"`, `clippy::pedantic = warn` (priority -1), `clippy::unwrap_used = "deny"`, `clippy::expect_used = "deny"` (tests may `#[allow]` both), `clippy::panic = "deny"`, `clippy::todo = "deny"`, `clippy::dbg_macro = "deny"`, `clippy::print_stdout = "deny"` and `clippy::print_stderr = "deny"` (only `main.rs`/`render` may `#[allow]` them).
- **Functional style:** immutable by default; no `mut` bindings outside local accumulation that clippy/perf justify; prefer iterator combinators, owned values returned from pure fns, no interior mutability except the completion cache file write.
- **FP helpers:** use `itertools` freely for iterator pipelines (`join`, `group_by`/`chunk_by`, `unique`, `partition_map`, `process_results`, …). Do not add `fp-core` or other HKT-emulation crates; `Option`/`Result`/`Iterator` combinators cover map/and_then/traverse (`collect::<Result<Vec<_>, _>>()`).
- **Types carry meaning:** newtypes for every identifier (`ProjectId`, `DatabaseId`, `CollectionId`, `DocId`, `FieldPath`, `UpdateTime`); parse-don't-validate (`FromStr`/`TryFrom` at the edge, infallible afterwards); illegal states unrepresentable (e.g. `SetMode`, `Guard`, `WriteAccess`). Fields of domain newtypes are private.
- Writes allowed only when the target matches `FIRECTL_WRITABLE` (comma-separated `db` or `project/db`, no wildcard, unset/empty = read-only). The denial message is exactly `writes are disabled for database <project>/<database>` and never mentions `FIRECTL_WRITABLE`.
- No interactive prompts anywhere.
- Env vars: `FIRECTL_PROJECT`, `FIRECTL_DATABASE`, `FIRECTL_WRITABLE`. Flags win over env. Database defaults to `(default)`.
- Output: default `table` on a TTY, `json` otherwise; JSON pretty on a TTY, compact otherwise; `jsonl` always compact; `--format`, `--pretty`, `--compact`, `--plain` override.
- Typed JSON tags: `$ts`, `$ref`, `$double`, `$bytes` (base64 standard), `$geo` (`{"lat":f64,"lng":f64}`). Document shape `{"_path": string, "_updateTime": string, "data": {...}}`.
- Exit codes (documented in `--help` long text): `0` ok, `1` other error, `2` usage (clap), `3` not found, `4` already exists, `5` precondition failed (changed since), `6` writes disabled, `7` missing index, `8` auth.
- Default `query` limit 100; `--all` removes it. *(Plan-author's call; spec left it to builder.)*
- **Traits only where there are multiple implementations.** The only trait is `port::Firestore` (impls: `grpc::GrpcFirestore`, test `FakeFirestore`). Domain logic, parsing, codecs, policy, rendering and app flow are concrete types and free functions — no traits for a single implementation. (Std trait impls like `FromStr`, `Display`, `TryFrom` are fine.)
- Uses raw `gcloud-sdk` protos instead of the `firestore` crate. *(Plan-author's call: our own `Value`/`Query` model maps 1:1 to the protos, and we need preconditions, transforms and the Admin API, which are cleaner raw.)*

## Review Focus

1. **Named-database routing:** every RPC must hit `projects/P/databases/D`, never silently `(default)` — test in Task 9 (`request_parent_uses_named_database`, `resource_prefix_is_database_path`).
2. **Field names needing quoting** (`my-field`, `with space`, `1st`, `` a`b ``): Firestore field paths must backtick-quote such segments — test in Task 2 (`field_path_quotes_non_identifier_segments`).
3. **Flag values with spaces/quotes/operators** (`name == "John Smith"`, `note == "a == b"`, `id in [a, "b c"]`) — test in Task 3.
4. **`_updateTime` nanosecond precision:** `--if-unchanged-since` must send exactly the value `get` printed; truncating to micros makes every guarded write fail — test in Task 4 (`update_time_roundtrips_nanos`) and Task 9 (`update_time_to_proto_keeps_nanos`).
5. **Not logged in / expired gcloud credentials:** the user should see "run `gcloud auth application-default login`", not a tonic stack — test in Task 9 (`auth_errors_map_to_auth_kind`) and Task 6 (exit code 8).

- Token rules: `null`/`true`/`false`; i64; f64 (contains `.` or exponent); `ts:<RFC3339>`; `ref:<docpath>`; `[a, b, "c d"]` list (only valid where an array is expected: `in`, `not-in`, `array-contains-any`, `+=`, `-=`, and `=` for array values); `"..."` forces string with `\"` escapes; anything else is a string.
- Filter grammar: `<field> <op> <value>`; ops `== != < <= > >= in not-in array-contains array-contains-any`. Split on the **first** operator token surrounded by whitespace; value is the rest, trimmed.
- Order: `field` (asc) or `field:asc|desc`.
- FieldOp: `field=value`, `field+=value|[..]`, `field-=value|[..]`; split on first `=`, `+=`, `-=` outside quotes.

- `required_index` rule: fields = equality filters (Asc, in filter order; `array-contains[-any]` → ArrayContains), then each `order` field with its direction, then inequality fields not already ordered (Asc). Return `None` when the field set has ≤ 1 distinct field, or when it is only equality filters with no order (Firestore merges single-field indexes).
